# UI language layer (English / ಕನ್ನಡ)

Tender Appendix 1 §45 requires a multilingual user interface. The web application ships in **English (India)** and
**Kannada**; the mechanism is language-agnostic, so a third language is one dictionary file.

## How it works

* **Keys are the English strings.** `t('Sign in')` returns the dictionary entry for the active language or the key
  itself, so English never needs a dictionary and an untranslated string degrades to English, never to a blank or an
  identifier. Placeholders use `{name}`: `t('{n} match(es)', { n })`.
* **Where translation happens.** The UI primitives translate centrally (`apps/web/src/components/ui/index.tsx`:
  `DataTable` headers, `Field` labels/hints, `Tabs`, `PageHeader`, `Card`, `StatusBadge`, `EmptyState`, `Modal`,
  `ConfirmDialog`, `Stat`, `KeyValue`), the shell translates navigation sections and labels, and every other visible
  literal in `apps/web/src` is wrapped in `t()` / `tNode()` (`apps/web/src/lib/i18n.tsx`).
* **Computed text.** Template literals become `t('{count} results', { count })` (placeholders let Kannada order the
  words itself; `null`/`undefined` render as empty), and literals inside ternary / `||` / `??` branches are wrapped
  individually. English plurals must not be built from fragments (`result${n === 1 ? '' : 's'}`): the codemod refuses
  them and asks for whole-sentence keys (`'1 result'` / `'{count} results'`).
* **Runtime values** (status enums, role names, permission descriptions, task labels) are translated when displayed:
  `titleCase()` returns an enum code's label in the active language, `Select` translates its plain-text options, and
  `StatusBadge` / role tables translate their values. Module-level registries (`label:` of tabs, nav items) are
  collected into the key list automatically; other runtime English forms are listed in
  `apps/web/src/i18n/extra-keys.json`. Codes without a dictionary entry (audit actions) keep their English label.
* **Switching.** `LanguageSwitcher` (top bar and sign-in page) stores the choice in `localStorage['ksp.lang']`, sets
  `<html lang>`, and remounts the application so every string re-renders. Dates, numbers and relative times format
  through `Intl` with the active locale (`apps/web/src/lib/format.ts`), e.g. `೧೨ ಸೆಪ್ಟೆಂಬರ್` is *not* used — Kannada
  text with Western digits is the KSP convention, matching the PDF reports.
* **Fonts.** The UI uses self-hosted Noto Sans with Noto Sans Kannada (OFL, `@fontsource-variable/*`, imported in
  `apps/web/src/main.tsx`; no CDN). Kannada glyphs fall through to Noto Sans Kannada by `unicode-range` in both
  languages, so Kannada free text also renders correctly in the English UI. The same two families are embedded in every
  generated PDF (custody reports, court export fact sheets, reports), so screen and print match. Identifiers use
  JetBrains Mono.
* **What stays English.** Evidence numbers, usernames, codes, hashes, file names, API error codes, log lines and the
  audit ledger (`action`, `details`) — these are identifiers and legal records, not UI copy. The Kannada word for a
  status is shown next to, never instead of, the stored value in exports.

## Dictionary workflow

```
node scripts/i18n/wrap-strings.mjs            # codemod: wrap new JSX literals/props/ternaries/templates in t(); refresh keys.json
node scripts/i18n/wrap-strings.mjs --check    # CI: fail if an unwrapped visible literal was introduced
node scripts/i18n/build-dictionary.mjs        # merge apps/web/src/i18n/kn/*.json → kn.json; print coverage
node scripts/i18n/build-dictionary.mjs --check   # CI: fail if any extracted string lacks a Kannada entry
node scripts/i18n/build-dictionary.mjs --missing # list untranslated keys
```

* `apps/web/src/i18n/keys.json` — every string the codemod found wrapped (2 181 at the time of writing; the
  2026-10-09 polish pass extended the extractor to template literals, ternaries and module-level registries, which
  surfaced ~450 strings that had been rendering in English inside the Kannada UI).
* `apps/web/src/i18n/kn/0N-*.json` — the Kannada dictionary in topic files (reviewable by a Kannada officer in any
  text editor); `kn.json` is the generated merge imported by the app. Coverage: **100 %** of extracted strings.
* The build script refuses empty translations and entries that drop a `{placeholder}`.

Terminology choices (consistent across the dictionary and the PDFs): evidence = ಸಾಕ್ಷ್ಯ, chain of custody =
ಪಾಲನಾ ಸರಪಳಿ, jurisdiction = ವ್ಯಾಪ್ತಿ, FIR = ಎಫ್‌ಐಆರ್, station = ಠಾಣೆ, retention = ಧಾರಣ, disposal = ವಿಲೇವಾರಿ,
legal hold = ಕಾನೂನು ಹೋಲ್ಡ್, audit ledger = ಲೆಕ್ಕಪರಿಶೋಧನಾ ಲೆಡ್ಜರ್, watchlist = ವಾಚ್‌ಲಿಸ್ಟ್. Product and protocol
names (AI, API, HLS, SHA-256, CCTNS, MFA) are kept in Latin script, as Karnataka government software does.

## Review status

The dictionary was written by the development team and has **not yet been reviewed by a Kannada language officer**
of KSP; a review pass before go-live is listed in the go-live checklist. Because keys are English, a corrected
translation is a one-line change in the topic file followed by `build-dictionary.mjs` — no code change, no release of
the API.

## Adding a language

1. Add it to `LANGUAGES` in `apps/web/src/lib/i18n.tsx` (code, label, locale, font class).
2. Create `apps/web/src/i18n/<code>/*.json` and extend `build-dictionary.mjs` to emit `<code>.json`.
3. Add a font-face if the script is not covered by the bundled fonts, and register the same font in
   `packages/core/src/pdf/` so PDFs can render the language.
